# 📦 Photo Archive Backup Utility — Project Plan

## 1. Purpose
Build a small, reliable Python application (later compiled to an EXE) that:

- Takes a **source folder** containing year → month → image subfolders  
- Creates a **single .7z archive** using 7‑Zip Store mode  
- Names the archive using the format:  
  **All_PC_Images_backup_YYYY_MM_DD.7z**
- Performs **two verification steps**:
  - 7‑Zip integrity test
  - SHA‑256 hash generation
- Lets the user **choose the destination drive** at runtime  
- Saves user preferences in a persistent **settings.json**  
- Runs manually as a Windows EXE  

This tool is designed for home use: simple, predictable, and safe.

## 3. Features & Behavior

### 3.1 Source Folder
- User selects a **root folder** containing year/month subfolders.
- The selected folder is saved in `settings.json`.
- On next run, the app loads the previous source folder automatically.

---

### 3.2 Archive Naming
Archive name format:

All_PC_Images_backup_YYYY_MM_DD.7z

Code

Example:

All_PC_Images_backup_2026_05_03.7z

Code

---

### 3.3 Archive Creation
Use 7‑Zip CLI:

7z a -t7z -m0=Copy "ARCHIVE_PATH" "SOURCE_FOLDER\*"

Code

- `-t7z` → 7z format  
- `-m0=Copy` → Store mode (no compression)  
- Must include all subfolders recursively  

---

### 3.4 Verification
Perform **both**:

#### 1. 7‑Zip integrity test
7z t ARCHIVE_PATH

Code

#### 2. SHA‑256 hash
- Generate SHA‑256 for the archive  
- Save as `ARCHIVE_NAME.sha256` next to the archive  

---

### 3.5 Destination Drive Selection
Because drive letters vary, the user selects the destination drive each run.

Implementation:

- Detect all mounted drives  
- Display a list (e.g., `E:\`, `F:\`, `G:\`)  
- User chooses one  
- Save last used drive in settings.json  

---

### 3.6 Settings File
Persistent `settings.json` should store:

```json
{
  "last_source_folder": "",
  "last_destination_drive": "",
  "last_archive_date": "",
  "7zip_path": ""
}
```
Behavior:

Load settings on startup

Pre-fill fields with previous values

If missing, prompt user and save

### 3.7 Logging
Create a log file for each run.

Logs stored in logs/ folder

Log filename: backup_YYYY_MM_DD_HHMMSS.log

Log entries:

Start time

Source folder

Destination drive

Archive name

Verification results

SHA‑256 hash

Errors
